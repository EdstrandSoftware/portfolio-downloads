# CSV Relay Lab — public workflow

This is a self-initiated, AI-assisted fictional demo, not a client project or a live integration. The owner has not yet personally practiced it. No paid demand, production reliability, or time saving is claimed. The two HTTP services are local simulations on `127.0.0.1`.

The approved film is a silent illustrated explanation with a typeset excerpt from saved results. Watching it does not run the software. The companion ZIP `csv-relay-motion-source.zip` contains `WORKFLOW.md` at its root and the runnable project at `api-transfer/toolproject/`.

## Requirements and setup

Use Python 3.10 or newer. The relay, helper scripts and tests use only the Python standard library. No installation or API credentials are needed. Extract the ZIP to a new folder and open a terminal at its root. On Linux or macOS:

```sh
cd api-transfer/toolproject
python3 scripts/run_demo.py --output runs/my-demo-run
```

On Windows PowerShell, use `py -3 scripts/run_demo.py --output runs\my-demo-run` from the same project folder. Linux was verified for this public package; the Windows and macOS commands are provided but were not executed here. Choose a fresh output folder for every run. The helper starts two temporary loopback HTTP servers, sets a fictional source token, runs the real CLI, saves evidence, and stops the servers.

Expected helper exit code: **0**. Its deliberately faulted phase has exit code **1** inside the successful scenario. Inspect `demo-summary.json`, `cli-transcript.txt`, `integrity-results.json`, `ambiguous-commit-proof.json`, and `server-events.json` in your chosen output folder. The receiver saves payloads and receipts in `receiver-receipts.sqlite`; the sender's progress ledger is separate in `audit-ledger.sqlite`. These files are generated by your run and are not in the ZIP.

| Phase | Expected result |
|---|---|
| Dry run | 8 checked; no POSTs, receipts, or ledger |
| Injected faults | 6 delivered, 2 failed |
| Failed-only recovery | 2 delivered, 6 completed batches skipped |
| Normal rerun | 8 skipped; 0 new POSTs or receipts |

The helper removes its two deliberately injected faults before recovery. Real failures require a person to diagnose and fix their cause before retrying. For `parts-005`, the first POST commits at the receiver but its reply is lost. The retry uses the same key and receives the original receipt: two requests, one stored receipt. The mock receiver atomically retains the key, original bytes, and receipt. A sender ledger by itself cannot guarantee that behavior.

## Ninth-batch exercise

From `api-transfer/toolproject/`, run:

```sh
python3 scripts/run_revision.py --output runs/my-revision-run
```

Use `py -3` instead of `python3` in Windows PowerShell. Expected helper exit code: **0**. This separate exercise starts fresh local services, seeds eight batches, adds fictional `revision/parts-009.csv` under a new batch ID, and shows why failed-only mode skips unseen work. Normal mode sends the ninth batch. Open `revision-summary.json` and `integrity-results.json` in the selected output folder.

| Phase | Delivered | Skipped | New POSTs | Total receipts |
|---|---:|---:|---:|---:|
| Seed eight | 8 | 0 | 8 | 8 |
| Failed-only after ninth arrives | 0 | 9 | 0 | 8 |
| Normal transfer | 1 | 8 | 1 | 9 |
| Normal rerun | 0 | 9 | 0 | 9 |

The original eight receipt IDs remain unchanged, and all nine received payloads match their fictional source bytes.

## Tests and source

From `api-transfer/toolproject/`, run:

```sh
python3 scripts/run_tests.py --output runs/my-tests
```

Expected: 26 tests, 0 failures, 0 errors, 0 skips, exit 0. The tests exercise real temporary loopback servers, including retries, auth, malformed receipts, changed identity, redirects, concurrent duplicate requests, and output collisions.

The ZIP includes the film's `render.py`, `art.py`, `api-transfer/scenes.py`, scene metadata, and its static proof image. Rendering is optional and needs pycairo plus FFmpeg with libx264, which are not installed by these instructions. The approved MP4 is supplied separately and should be used as the viewing copy. The film drawing code creates frames; it does not execute transfers.

The relay does not parse, clean, or validate business meaning in the CSVs. Byte equality covers the supplied fictional inputs only. There is no live SaaS connection, TLS, external network integration, production credential handling, throughput guarantee, or deployment claim.
